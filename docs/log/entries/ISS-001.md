# ISS-001 — Admin page landing not set
- Reported: 2026-11-07
- Type: issue
- Priority: P3 (proposed by Claude: not stated by the user, follows from the workaround below; the user can change it)
- Area: core, admin UI
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "admin page landing not set" (as reported; no further detail given)
- Workaround: enter the full URL of the page wanted, instead of going through the admin login (as stated by the user)
- Expected / proposed: defined in Core 0.39 as CORE-378 (extends CORE-62 and CORE-253): an admin page without a valid session answers 303 to `/admin/login?next=<path and query>`; after a successful login the browser goes to `next` when it is under `/admin`, otherwise to `/admin`, the admin home with the status (CORE-305); `/admin/login` with a valid session goes to `/admin`; API routes keep answering 401.
- Requirements: spec gap, closed in Core 0.39: CORE-378 added. Related: CORE-62, CORE-253, CORE-305.
- Spec check: 2026-11-07, Core spec 0.38 (the Module Contract and the implementation plan were not checked). Searched the text for "landing", "redirect", "login" and "/admin". Found, none saying what `/admin` or the login lead to: `/admin` as the admin single-page UI, `/admin/config` (CORE-322), `/admin/debug`, `/admin/widgets`, `/admin/ext/<module>` (CORE-329), token or session needed for `/admin` (CORE-62), `/admin/login` exchanging a token for a session cookie (CORE-253). The only redirect on a login-like flow is `/pair` to `/` (CORE-254), for displays, not for the admin. Result: confirmed as a spec gap (the user's assumption holds).
- Status: in progress — spec written in Core spec 0.39 (CORE-378, Document history row 0.39 with `Source: … ISS-001 …`); spec sync PR #100 (squash-merged 2026-11-13); code merged as PR #109 (branch `feat/iss-001-admin-landing`), squash-merged 2026-11-13 (8a59b73). The user decides when it is fixed.
