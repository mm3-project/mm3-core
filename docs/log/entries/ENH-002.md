# ENH-002 — No option to restart the application or the system
- Reported: 2026-11-07
- Type: enhancement (as reported by the user)
- Priority: P3 (set by the user: "low pri", because a workaround exists; on the enhancement scale "maybe in the future")
- Area: core, admin UI, installer, system (privileges)
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "Option to restart the application, restart the system" (as reported). Not stated: where the option should be (the admin UI, the CLI, the REST API, Home Assistant), and which application restart is meant (the engine `mm3.service`, the kiosk `mm3-kiosk.service`, or both).
- Workaround: in the development phase, access to the machine by ssh (as stated by the user). The workaround holds only while ssh access exists, which is the reason for the low priority.
- Expected / proposed: defined in Core 0.42 (the user's decisions of 2026-11-14, with Claude's proposals accepted). CORE-382: `POST /api/v1/system/restart-engine`, `restart-kiosk` and `reboot` on the admin listener (not on the admin socket), no body, no passphrase or code; the engine forwards to the installer, which answers 202, waits 2 s and runs `systemctl restart mm3.service`, `systemctl restart mm3-kiosk.service` or `systemctl reboot` through its polkit rule, and logs the action with the caller; 409 `CORE_API_INSTALLER_BUSY` while an installer operation or restore runs or an earlier system action is pending; 503 `CORE_API_INSTALLER_UNAVAILABLE` without the installer (so all three need the installer); 409 `CORE_API_NO_KIOSK` when the kiosk unit is not installed; no new problem code. CORE-383: a System card on the admin home with the buttons "Restart engine", "Restart kiosk" and "Reboot system", each behind a confirmation dialog (Cancel focused, no passphrase); disabled with the reason while the installer is unreachable or busy; a banner while the action runs; while the engine is down the page keeps its content, the indicator shows "unavailable" and the page reconnects on the schedule of CORE-250 (0.5 s doubling to 10 s) without a limit; the banner ends when the status shows a later `started_at` (engine, reboot) or the kiosk back (`kiosk.connected`), or after 120 s with a message. The kiosk keeps its last render while the engine restarts (CORE-250). Not done, as decided: a CLI command, Home Assistant or MQTT entities, a re-authentication. The points listed when it was reported (where each option lives, what "the application" means, privileges, confirmation, what the kiosk shows, reboot only with the installer, the admin page while the engine is down) are all settled in CORE-382 and CORE-383.
- Requirements: Core 0.42: CORE-382 (restart and reboot routes, done by the installer) and CORE-383 (System controls in the admin) added; CORE-357 and CORE-359 changed (the installer's polkit rule covers the kiosk unit and the reboot).
