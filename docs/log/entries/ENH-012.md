# ENH-012 — The same style for the whole admin interface, not one page
- Reported: 2026-11-14 (from ENH-002, when the user asked whether variant B applies to all the admin UI)
- Type: enhancement (the spec had no rule for a common look of the admin pages beyond CORE-383 for the System card; closed in Core 0.43, see Spec check; the user can change this)
- Priority: P3 (proposed by Claude: the user gave none; nothing is broken and the pages work; the user can change it)
- Area: admin UI, all pages (home, editor, history, debug, extensions), front-end
- Spec versions at report: Core spec 0.42, Module Contract 1.0 rev 15
- Description: the user chose variant B of the ENH-002 mockups (a row per action with its effect, a confirmation dialog with Cancel focused, banners, disabled controls with the reason as tooltip) and asked whether it applies to all the admin UI. Claude answered that it applies to the System card only. The user replied: "In realtà io voglio che lo stesso stile si applichi a tutta l'interfaccia admin dello specchio non solo una pagina" (what the user wants is the same style on the whole admin interface of the mirror, not on one page), and said yes to logging it. Not stated: which elements count as "the style" (the layout of rows, the dialogs, the banners, the colours), and whether the old look has to stay as an alternative (that is ENH-005).
- Workaround: none needed; the pages work as they are.
- Expected / proposed: defined on 2026-11-14 in Core 0.43 (§9.1, milestone 6): four patterns become common to every admin page. CORE-384 confirmation dialogs (title, one sentence on the effect, Cancel with the focus, Escape and the backdrop cancel, a red confirm button only for a destructive action: reboot and replacing the draft; never the browser's own box). CORE-385 form and preview dialogs (title, one sentence that says where the change lands and what is saved, the first field focused, or Close for a read-only dialog, actions in a row at the end). CORE-386 action rows (each action a row with its effect; a control that cannot run is disabled with the reason as the tooltip and shown next to it). CORE-387 banners (four kinds: error, warning, information, done; `role="alert"` for errors, `role="status"` for the others; a done banner clears after 8 s). Built on the shared `adminui/ui.js` (`banner`, `Messages`, `actionRow`, `confirmDialog`, `closeOnBackdrop`).
- Requirements: Core 0.43: CORE-384, CORE-385, CORE-386, CORE-387 added (§9.1; milestone 6, which the change reopens through the `spec-change` issue, CORE-79). Related: CORE-383, CORE-381, CORE-322, CORE-302, CORE-63 (no inline styles), ENH-005 (kept separate).
- Spec check: spec not yet checked beyond what ENH-002 showed. Code check, 2026-11-14, `src/mm3/core/web/adminui/` on main (b6c0ce8): all admin pages use one stylesheet `admin.css`, so colours, buttons and alerts are common; the row layout of variant B (`.system-row`) is used only by the System card (`system.js`, `home.js`); the other dialogs (the review of changes in `config.js`, the restore confirmation in `history.js`) are not unified with the System card's confirmation dialog; the classes `button.danger`, `.alert.info`, `.alert.ok`, `button[aria-disabled="true"]` and `dialog.system-confirm` are in `admin.css` and used only by the System card. Not searched: the Core spec text for admin look rules. Result when the entry was taken up (Core 0.42): no requirement for a common style beyond CORE-383, so a gap; closed by CORE-384..387 in Core 0.43.
- Status: in progress — spec: Core 0.43, spec sync PR #116 (branch `docs/spec-0.43-admin-style`), squash-merged 2026-11-14 (9d08325); code: PR #117 (branch `feat/enh-012-admin-style`), squash-merged 2026-11-14 (8a5df5b). Not verified on a real mirror. The user decides when it is fixed.
