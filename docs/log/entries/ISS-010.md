# ISS-010 — Save refused after removing a required field shows only "error"
- Reported: 2026-11-12
- Type: issue (the user did not name a type; the spec check shows that explicit, localized messages are already required, see Spec check, so Claude typed it as an issue; the user can change this)
- Priority: P2 (set by the user: "pri 2 non blocking")
- Area: admin UI, editor, validation messages
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "when I hit remove I cannot save with an error. that is fine. however the error message shall be more explicit. it is just "error" now." (as reported). The "remove" is the delete button on a module's `id` or `position` field in the form (see the chat of 2026-11-12); the refusal to save is accepted by the user, and only the message is the problem. Not stated: where the word "error" appears (a toast or banner at Save, next to the field, or on the layout card), the language of the admin, which field was removed, and whether the field itself is marked.
- Workaround: not stated
- Expected / proposed: a message that says what is wrong and where, for example that the field is required and which one, in the language of the admin session, shown on the field as the spec describes. The refusal to save stays as it is.
- Requirements: the "Validation while editing" requirement of the editor (forms validate each field on change, the YAML view checks syntax and schema 300 ms after the last keystroke; errors show inline on the field, on the layout card and in the YAML gutter, with localized messages); CORE-33 (`position` is required for a module with a front-end); the validation code `CORE_CFG_REQUIRED` of the core spec. Not a spec gap.
- Spec check: 2026-11-12, Core spec 0.38, (the Module Contract, the implementation plan and the code were not checked). Searched "inline", "validation error" and "CORE_CFG_REQUIRED", and read CORE-33. Found: the "Validation while editing" item above (a bullet in the editor section; it has no CORE id of its own in the text found, and it points to CORE-323 for the YAML editor); CORE-33, `position` required for a module with a front-end and an error for a backend-only module; `CORE_CFG_REQUIRED` listed among the validation codes (its message text was not read). Result: the requirement of explicit, localized, inline messages exists, so a bare "error" at save deviates from it. Not found, so not claimed: what message text each code has, and whether the Save action itself (as opposed to editing a field) is required to list the validation errors.
- Status: fixed — PR #97 (squash-merged 2026-11-13), developed against the validation requirement, CORE-33, CORE-35 and CORE-206, with no spec change (Core spec 0.38 unchanged). Set on the user's message "ok closed Round1 PRA".
- Resolved in: PR #97 (merge commit be1f2513, 2026-11-13); no spec version change, no Document history row; no release noted. What changed: the admin texts endpoint now serves the `CORE_CFG_*` catalog keys (`ADMIN_PREFIXES` in `pages.py`) and a new `recordText(r)` shows the localized text of a validation record's `code`, with its params, falling back to the engine message; the Form shows section-level errors at the top of the form; the save bar's error count opens a list of errors that link to the Form sections; the YAML gutter and the record lists use the same text.
