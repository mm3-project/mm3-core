# ENH-004 — Undo/redo log of the draft to live from the last saved version until the next save; no save prompt every time
- Reported: 2026-11-07
- Type: enhancement (as reported by the user)
- Priority: P2 (proposed by Claude: not stated by the user; nice to have)
- Area: admin UI, editor, configuration history
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: from the message "enhancement add undo redo buttons in the layout ui. do not ask to save everytime. pinned versions are the saved ones. undo redo log lives from last pinned verison until save" (as reported; the buttons are ISS-004). The user defines "pinned versions" as the saved ones. Read as: the undo and redo log of the editor starts at the last saved version and lasts until the next save, and the editor does not ask the user to save every time. Not stated: which prompt asks to save every time, and when it appears; whether the log has to survive a page reload.
- Workaround: not stated
- Expected / proposed: defined in Core 0.39. CORE-377 (extends CORE-151): the draft history starts at the version the draft was loaded from (the current version or one opened from History), is kept in the browser with the draft so a page reload keeps both, is cleared only by Save, Discard or loading another version, holds up to 500 steps, and Undo is disabled at its start. CORE-302 changed: the prompt the user saw was the diff preview before Save that CORE-302 required (confirmed by the user on 2026-11-13); Save now writes without a confirmation or preview, and the diff is shown only on request in "Review changes".
- Requirements: Core 0.39: CORE-377 added, CORE-302 changed. Related: CORE-151 (the editor's undo/redo history of the draft), CORE-152 (section undo), CORE-154 (undo and redo of saves in the history), CORE-322 and CORE-324 (Open in editor loads a version as a draft).
- Spec check: 2026-11-07, Core spec 0.38 (the Module Contract and the implementation plan were not checked; the code was not checked; CORE-154 and CORE-322 only as seen in the text found by search). Searched "CORE-151:", "pinned", "pin" (too broad, found only unrelated uses), "unsaved" and "discard". Found:
  - CORE-151: one undo/redo history for the current draft, shared by the layout, form and YAML views, at least 200 steps.
  - The next item of the same list ("Editor level (unsaved changes)"): typing in the YAML view is grouped into one step per pause of 1 s or per view switch; the history is lost on page reload; the draft itself is kept in the browser until saved or discarded.
  - CORE-154 (the level of the configuration history, saved versions): "Undo last save" creates a new version with the content of the current version's parent, and "Redo" a new version with the content undone most recently. This is a different level from the editor's log.
  - "Pinned" in the spec means other things (pinned npm packages, the pinned page of the preview, pinned dependency versions); it is not a term for saved versions. The spec calls them versions of the configuration history.
  Result: the user's assumption (a gap) is confirmed as far as searched. The spec gives the editor's log the life of the draft, which is kept until saved or discarded, but says nothing about what happens to the log at a save, and the log is lost on a page reload. No requirement was found that asks the user to save, so the prompt the user sees is not in the spec text read. The term "pinned version" is the user's.
  Third check, 2026-11-13, Core spec 0.38, in the Core 0.39 session: CORE-302 says "the admin shows `diff` as the preview before Save", which is the save prompt; the first check had missed it.
