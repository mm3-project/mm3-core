# ENH-014 — A helper tool for publishing modules to PyPI
- Reported: 2026-11-16 (the user's "add as low priority enhancement an helper tool for publising modules to pypi", after Claude explained in plain terms what PyPI and Trusted Publishing need; the user said they are not familiar with PyPI)
- Type: enhancement (the specs require Trusted Publishing but define no tool that helps a module author set it up; see Spec check)
- Priority: P3 (set by the user: "low priority"; maps to "maybe in the future"; the manual steps are a workaround)
- Area: tooling (`mm3 new-module` scaffold, the `mm3` CLI), catalog, specs
- Spec versions at report: Core spec 0.45, Module Contract 1.0 rev 15
- Description: "add as low priority enhancement an helper tool for publising modules to pypi". Context, from the chat of 2026-11-15 and 2026-11-16: the first real module for the catalog test, `mm3-hello`, was scaffolded with `mm3 new-module hello --kind frontend`, and its CI workflow and its `publish.yml` (Trusted Publishing with attestations) were written by hand by Claude, because the scaffold writes neither. What an author still has to do alone is the part least known to a newcomer: a PyPI account with two-factor login, a pending trusted publisher on PyPI (project name, owner, repository, workflow file name, environment name), the `pypi` environment in the GitHub repository, and a GitHub release whose tag equals the version.
- Workaround: follow the steps explained in the chat on 2026-11-16 (PyPI account, GitHub repository, pending publisher, `pypi` environment, release with the matching tag) and copy `.github/workflows/publish.yml` and `ci.yml` of `mm3-hello` (given to the user as `mm3-hello.tar.gz`; not in a repository yet).
- Expected / proposed: not decided. Ideas for when it is defined: (a) the scaffold also writes `publish.yml` and a CI workflow for the module, with the pre-1.0 installation of `mm3-core` and `mm3-build` from a pinned commit replaced by `pip install` after release 1.0; (b) a command, for example `mm3 module publish-check` or `mm3 module publish-setup`, that checks the project before a release (tag equals version, README has the "Grants" and "Notifications" sections of MOD-97, the five-language description of MOD-98, the wheel passes `mm3 module check --wheel --only static`) and prints the exact values to enter in the PyPI pending-publisher form and the steps still to do; (c) a draft `modules/<name>.yaml` entry for module-index. Boundary to keep: the helper never uploads from the author's machine and never stores a PyPI token, because MOD-96 allows only Trusted Publishing and the index rejects token uploads. Points to settle: scaffold or separate command; whether it runs `gh` for the GitHub side or only prints instructions; one workflow for a monorepo module (as `mm3-clock` in mm3-core, whose README check in module-index reads the repository's root README, see the chat of 2026-11-15) or for a repository of its own.
- Requirements: none: spec gap, as far as searched (see Spec check). Related: MOD-95..99 and Contract §12.3 (publishing to the catalog; the scaffold), CORE-281 (`mm3 new-module`, `mm3 module check`), CORE-280 (`mm3-build`), CORE-121, CORE-123 (index builder), CORE-371 (wheel check).
- Spec check: 2026-11-16, Core spec 0.45 and Module Contract 1.0 rev 15, searched in the exports `docs/spec/core.md` and `docs/spec/contract.md` in mm3-core for "publish", "new-module", "Trusted Publishing" and "MOD-96". Found: MOD-96 (releases MUST be uploaded with Trusted Publishing from the module's public repository; token uploads are rejected by the index), MOD-95, MOD-97, MOD-98, the Contract's scaffold paragraph (`mm3 new-module` writes the package, five catalogs, a README with the two sections and a sample test; no workflow) and the CLI list of CORE-281 (no publishing command). The code of the scaffold (`src/mm3/cli/new_module_cmd.py`) was also read: it writes no workflow file. Not searched: the implementation plan (whether a publishing helper is planned for milestone 9 or 10) and the Contract's section 12 text beyond the lines found. Result: confirmed as far as searched: the specs require Trusted Publishing but define no helper, so it is a spec gap and goes through the defining phase before any code.
