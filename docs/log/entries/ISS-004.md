# ISS-004 — No undo and redo buttons in the Layout view
- Reported: 2026-11-07
- Type: issue (the user reported the whole message as an enhancement; the spec check shows that this part is already required, see Spec check, so Claude typed it as an issue; the user can change this). The other parts of the message are in ENH-004.
- Priority: P3 (proposed by Claude: not stated by the user; the spec gives keyboard shortcuts for the same function, which would be the workaround; the user can change it)
- Area: admin UI, layout view
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "add undo redo buttons in the layout ui" (as reported, within the message "enhancement add undo redo buttons in the layout ui. do not ask to save everytime. pinned versions are the saved ones. undo redo log lives from last pinned verison until save"). The user did not say which buttons exist today.
- Workaround: the keyboard shortcuts Ctrl+Z (undo) and Ctrl+Shift+Z or Ctrl+Y (redo), which CORE-151 requires. Not verified in practice.
- Expected / proposed: undo and redo buttons in the Layout view, as CORE-151 requires toolbar buttons for the editor. If the buttons are missing, this is developed against CORE-151 without a spec change. Points to check when it is developed: in which toolbar CORE-151 means the buttons to be (the spec says "toolbar buttons" for the editor, shared by the layout, form and YAML views, and does not say where they sit); whether the Form and YAML views have them.
- Requirements: CORE-151 (the admin editor keeps one undo/redo history for the current draft, shared by the layout, form and YAML views: Ctrl+Z, Ctrl+Shift+Z or Ctrl+Y, plus toolbar buttons; each step a JSON Patch with a readable label; at least 200 steps). Related: CORE-326 (every overlay edit in the Layout view is one draft step, CORE-151), CORE-328 (the overlay toolbar of the selected instance, which lists no undo or redo).
- Spec check: 2026-11-07, Core spec 0.38 (the Module Contract and the implementation plan were not checked; the code was not checked). Searched "CORE-151:", "pinned", "pin", "unsaved" and "discard", and read the list that holds CORE-151 and CORE-152. Found: see the text of CORE-151 above and, in the same list, CORE-152 (section undo: "Undo last change here" on each module card, form and section). CORE-326 says every overlay edit is one draft step, so Layout edits are undoable. CORE-328 lists the controls of the overlay toolbar for the selected instance (`z`, preset, `appearance.*`, Enable or Disable, Edit in Form, Rescale proportionally) and no undo or redo, so the buttons of CORE-151 belong to another toolbar of the editor, whose place the spec does not give. Result: the user's assumption (an enhancement) is not confirmed for the buttons: the spec already requires toolbar buttons for undo and redo in the editor, shared by the three views. If the Layout view has none, that deviates from CORE-151 as I read it; whether the spec puts the buttons in the Layout view specifically is not stated. Code check, 2026-11-13, mm3-core main at be1f251 (after PR #97): `src/mm3/core/web/adminui/config.js` renders Undo and Redo buttons, with the label of the next step, at the right of the tab bar of `/admin/config` on the Layout, Form and YAML tabs (not on History, which has the save-level undo of CORE-154). Verified in Chromium with Playwright: the button is present on the Layout tab and undoes three overlay moves one by one.
- Status: done — no code change: the buttons of CORE-151 are already present in the tab bar on the Layout tab; the user confirmed on 2026-11-13 that they see them
