# ISS-011 — No way to add or delete a module in the admin UI
- Reported: 2026-11-12 (as ENH-008; moved here the same day)
- Type: issue (reported as missing; the spec check shows that adding and deleting are already required in the Layout view, see Spec check, so this is a deviation, not a gap; the user can change this). Since 2026-11-13 the add part also showed a spec gap (no route lists the installed modules, see Spec check), closed in Core 0.40 (CORE-380) before that part was coded.
- Priority: P1 (the user said "pri high"; on the issue scale P1 means hindering or blocking, and a workaround exists, which on the scale would be P3, so this is the user's choice of urgency; the user can change it)
- Area: admin UI, layout view (editing overlay and toolbar)
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "there is no way to add or remove or move a module in the admin ui" (as reported; moving was withdrawn by the user, ISS-009, because it works). The user then stated that there is no catalogue in the admin GUI (2026-11-12). Not stated: whether a delete control exists anywhere (the user saw delete buttons on the `id` and `position` fields of the form, which clear a field value and do not delete the module as far as known).
- Workaround: edit the `modules` list in the YAML (as stated by the user).
- Expected / proposed: numbered in Core 0.39. CORE-374 (add an instance, extends CORE-326 and CORE-328): "Add module" in the Layout view lists the installed modules (Core 0.39 text: from `GET /api/v1/modules`; Core 0.40: from `GET /api/v1/installed-modules`, CORE-380); the dialog asks for the module and, for a front-end module, a region preset (default `top_left`, the user's choice of 2026-11-13); one draft step appends the instance with an id always written (`<module>`, then `<module>_2`, …; a sibling without an explicit id gets its default id written), `position` the preset, `config: {}`, `pages: [<selected page>]` when a `pages` block exists; a backend-only module goes to the Services lane; errors of the new instance block Save. CORE-375 (delete an instance): "Delete" in the overlay toolbar, on Services cards and in the disabled list, one undoable draft step without a confirmation, removing the whole entry; saving stops the instance and keeps its stored data. **Open point found on 2026-11-13, closed in Core 0.40 the same day:** the route named in CORE-374 returned the configured instances, not the installed modules (see Spec check), so CORE-374 as written could not be built. Core 0.40 adds CORE-380, `GET /api/v1/installed-modules` (read-only, sorted by `name`, each module with `version`, `distribution`, `kind`, `header` in the admin language, `usable`, `error` and its instances; a module the registry refused is listed with its reason and is never offered by Add module; the path is outside `/api/v1/modules/<instance id>/`, CORE-332), and CORE-374 changed to read it. The user decided on 2026-11-13 to split PR C: C1 (delete, pages) first, C2 (Add module, Services lane) after that session.
- Requirements: the Layout view requirement of the editor section, numbered in Core 0.39 as CORE-374 and CORE-375 (the Layout view bullet now cites them); CORE-380 added in Core 0.40 (installed modules route; CORE-374 changed). Related: CORE-326 (overlay: move, resize, disabled instances listed with an Enable action), CORE-328 (toolbar: Enable or Disable, Edit in Form), CORE-202 (instance keys and ids), CORE-35 (Save is disabled while any error remains), CORE-315 (`GET /api/v1/modules` = instances), CORE-332 (module routes). Pages: ENH-001, CORE-376. Spec gap: no requirement for a route that lists the installed modules, closed in Core 0.40 (CORE-380 added, CORE-374 changed).
- Spec check: 2026-11-12, Core spec 0.38 (the Module Contract and the implementation plan were not checked; the code was not checked). Found by search for "disabled" in the editor section: the Layout view requirement above. Also read CORE-326, CORE-328 and CORE-202. Result: the user's assumption (no such function, a gap) is not confirmed. The spec requires adding from a catalog and deleting in the Layout view, so their absence deviates from it. Implementation plan, read on 2026-11-12 (searched "catalog" and "Layout view"; read the milestone status and the milestone 6 and 7 passages): milestone 6 is done, and its part D2 (PR #74) is described as "the Layout tab with preview, overlay, page selector, toolbar and Show on mirror"; neither the plan text read nor CORE-326 or CORE-328 mention adding an instance or deleting one. So the sentence in the Layout view bullet was never turned into numbered requirements and, as far as the plan shows, never built or assigned to a milestone. The "catalog" of milestone 7 (part C, CORE-349..358) is the signed module-index catalog of the installer, to browse and install new modules; its definition is complete and development is next. The catalog the Layout view needs is only the list of installed modules. Not found, so not claimed: where the catalog and the delete control must be in the Layout view (the toolbar of CORE-328 does not list delete), and what is asked for when adding (id, position, pages), which the spec leaves open as far as read. Re-checked on 2026-11-13 in Core spec 0.38 before writing 0.39: the Layout view bullet is still the only text; CORE-326 and CORE-328 have no add or delete.
  **Correction, 2026-11-13 (PR C1 development, Core spec 0.39, `docs/spec/core.md` and `src/mm3/core/web/api.py`):** the statement of 2026-11-12 and the round 1 plan note that the installed-modules list "the engine already has (`GET /api/v1/modules`, CORE-315, CORE-330)" was wrong. CORE-315 defines `GET /api/v1/modules` as the list of configured **instances** (state, health, controls), and the route in `api.py` returns that. The spec has no route for the installed modules (the module packages that can be instantiated), so the dialog of CORE-374 has nothing to read. Claude's mistake, made while reading the spec for the 0.39 definition and not caught there. This is a spec gap inside CORE-374, closed by the defining session named above (Core 0.40, CORE-380).
