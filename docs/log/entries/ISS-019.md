# ISS-019 — Intermittent hang in `tests/test_hot_reload.py` on Python 3.11
- Reported: 2026-11-20 (seen once in CI on PR #153, job `test (3.11)`; logged on the user's "Yes" to Claude's proposal)
- Type: issue (a test run that gives different results on identical runs; the cause is not known; the user can change this)
- Priority: P2 (proposed by Claude: it fails a required CI job at random and a re-run clears it, so it is not blocking; the user can change it)
- Area: CI, tests (`tests/test_hot_reload.py`), possibly the engine's shutdown of a task left running
- Spec versions at report: Core spec 0.56, Module Contract 1.0 rev 16
- Description: on PR #153 (milestone 8 step 6a) the job `test (3.11)` of CI run 44750016425 printed `tests/test_history.py` at 14:09:21 and then `Timeout (0:02:00)!` from faulthandler at 14:11:21, again every two minutes, until the job was cancelled at 14:32. The stack shows the main thread in `pytest_asyncio`'s fixture finalizer, in `run_until_complete` waiting in `select`, with one idle `concurrent.futures` worker and one idle anyio worker thread. The file after `test_history.py` is `test_hot_reload.py`. The jobs on 3.12, 3.13 and 3.14 passed, #157 (which held the same code) passed on 3.11 at the same time, and the re-run passed. PR #153 changes no hot-reload code. 15 local runs of `test_hot_reload.py` on 3.11 did not hang.
- Workaround: re-run the failed job (done on 2026-11-20).
- Expected / proposed: the test file never hangs; a teardown that cannot finish fails in seconds with the name of the task it waits for.
- Requirements: CORE-208..211 (hot reload) are what the tests cover; no spec change known.
- Spec check: spec not yet checked; the test file and the engine's stop path not yet read.
