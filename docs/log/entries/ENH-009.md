# ENH-009 — Make the confirmation dialog in the admin optional
- Reported: 2026-11-12
- Type: enhancement (the spec requires confirmations in places and has no setting to switch them off, see Spec check; the user can change this)
- Priority: P3 (low, set by the user; a workaround exists)
- Area: admin UI, confirmation dialogs
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "make the confirmation dialogue in admin optional. low pri workaround confirm everytime" (as reported). The user then said it is the dialog shown when saving changes. Not stated: where the choice should live (a setting, a "don't ask again" box).
- Workaround: confirm every time.
- Expected / proposed: the confirmation dialog can be switched off. Points to settle when it is defined: the save dialog is the one asked for, whether others (restore) may be optional too; where the setting is kept (per browser or in the configuration); that no dialog required for safety is switched off (the installer confirmation of CORE-132 uses a passphrase and stays); the default (on).
- Requirements: none: spec gap. Related: CORE-322 (Restore all and Restore section after a confirmation that shows the diff), CORE-132 and CORE-133 (installer confirmation).
- Spec check: 2026-11-12, Core spec 0.38 (the Module Contract, the plan and the code were not checked). Searched "confirm". Found: CORE-322 (restore after a confirmation with the diff), CORE-132/133 (installer), WGT-22 (a widget control with a second tap). No requirement of a confirmation for save or delete in the admin, and no setting to turn confirmations off. Result: the user's assumption of a gap is confirmed. The dialog the user means is the one shown when saving changes: the spec read has no requirement for a confirmation on save (CORE-35 only disables Save while errors remain), so this dialog is not specified, and what it shows is not known. Not found, so not claimed: the text and purpose of the save dialog. Correction, 2026-11-13: the save dialog is the diff preview that CORE-302 required before Save, missed by this check; Core 0.39 removes it (ENH-004).
- Status: rejected — superseded by ENH-004 on the user's decision (2026-11-12): the editor does not ask to save or confirm the save, so there is no dialog left to make optional. Confirmations required elsewhere (restore with diff, CORE-322; installer, CORE-132) are not affected
