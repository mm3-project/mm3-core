# ISS-012 — Form view edits fail with 422 CORE_API_PATCH_FAILED when the key is not in the config (first seen on the pages list)
- Reported: 2026-11-12 (with a screenshot of the Form view)
- Type: issue (the Form view shows a `pages` section with a list and an "Aggiungi" (Add) button, so the function is offered; a dead button deviates from the spec, see Spec check; the user can change this)
- Priority: P1 (set by the user on 2026-11-12, raised from P2 proposed by Claude; a workaround exists, the YAML view, but the user wants the YAML to be a backup and last resort, so the Form view must work for lists; the user can change it)
- Area: admin UI, Form view (list control, toggles; first seen in the `pages` section)
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "there is a pages entry in the admin ui with an add (aggiungi) but it does not work." Screenshot: the Form view with the sidebar (engine, display, audio, layout, pages, backup, then the modules clock, weather_home, weather_daily) and the `pages` section with the fields Default (empty), Rotate, Pause On Interaction, Reset On Resume (checkbox), Return After, Transition (select, "–") and a List with an "Aggiungi" button. The user then answered (2026-11-12): clicking Add gives the error "it was not possible to apply the change" and the user cannot save. Not stated: the exact wording in the language shown, the browser console and network output, and whether list items have a delete control.
- Workaround: edit the `pages` list in the YAML view.
- Expected / proposed: the Add button appends a page to the draft (an id and a title, with the rules of CORE-230); the draft shows it in the Form, the YAML and the Layout page selector, and Save writes it.
- Requirements: the Form view requirement of the editor section (a form generated from the schema: text, number, enum, toggles, lists, nested objects, duration and time pickers, secret field); CORE-301 (the Form view reads `documents` and writes nothing; edits are the draft as JSON Patch); CORE-230 (`pages`: id `[a-z][a-z0-9_]{0,31}`, unique, at most 32, `default`, `title`); CORE-322 (the page has the tabs Layout, Form, YAML, History). Not a spec gap.
- Spec check: 2026-11-12, Core spec 0.38 (the Module Contract, the implementation plan and the code were not checked). Searched "Form view", "CORE-230" and "list of objects". Found: lists are required in the generated Form; the Form edits the draft through JSON Patch; the `pages` rules above. Result: the user's report is not a spec gap; a list control that cannot add an item deviates from the Form view requirement. The error message matches the failure of CORE-301: an operation of the draft patch that cannot be applied returns 422 `CORE_API_PATCH_FAILED` naming its index; this is a likely reading, not confirmed (the response was not seen). Not found, so not claimed: a rule for the list of objects (what the control asks for, the default values of a new item), and the cause (the Add control may send an operation that does not fit the document, for example a path that does not exist yet; or the `pages` schema shown in the Form, with the fields Default, Rotate, Pause On Interaction, Return After and Transition, may differ from the `pages` key of CORE-230; neither checked).
- Status: fixed — PR #97 (squash-merged 2026-11-13), developed against the Form view requirement and CORE-301, with no spec change (Core spec 0.38 unchanged). Set on the user's message "ok closed Round1 PRA".
- Resolved in: PR #97 (merge commit be1f2513, 2026-11-13); no spec version change, no Document history row; no release noted. What changed: `draft.js` has a new `setOp(doc, target, value)` that builds the one operation that fits the document: it creates all missing parents from the file root in a single `add`, replaces a `null` section, appends with `-`, and returns nothing for a scalar parent; the Form's `formChange` uses it. Tests: `test_core_301_form_ops_create_missing_parents` and `test_core_301_form_edit_in_an_absent_section_applies`.
