# ENH-008 — No way to add or remove a module (instance) in the admin UI
- Reported: 2026-11-12
- Type: enhancement (the user thinks "no way"; the spec check confirms that no requirement defines it, see Spec check)
- Priority: P1 (the user said "pri high"; on the enhancement scale P1 means major; a workaround exists; the user can change it)
- Area: admin UI, layout view and form view, module instances
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "there is no way to add or remove or move a module in the admin ui" (as reported; the add and remove part). Not stated: whether adding means placing a new instance of an installed module or installing a module from the catalog; where in the interface it is expected (the Layout view, the Form view, a modules page).
- Workaround: edit the `modules` list in the YAML (as stated by the user). The YAML tab exists (CORE-322); not verified in practice for adding and removing.
- Expected / proposed: add a module instance from the installed modules (choose the module, an id, a page or pages, a position, the config from its form) and remove an instance, in the admin UI. Points to settle when it is defined: where it lives (an "Add module" action and a palette in the Layout view, or the Form view); the list of installed modules offered, and whether installing from the catalog is a separate function; the instance id rules and defaults; the initial position (a free spot in the grid, or a preset) and validation (CORE-326 red rule); which pages it appears on; removing an instance and what happens to its data and to its entries in `positions` and `pages`; a confirmation; the file that holds the instance (CORE-301); undo of both as draft steps (CORE-151, ISS-008); how it relates to disabling (CORE-328) and to ENH-001 (adding and removing pages), which should be defined together.
- Requirements: none: spec gap. Related, likely to be extended or changed: CORE-322 (the admin config page), CORE-326 (editing overlay), CORE-328 (the overlay toolbar of the selected instance: z, preset, appearance, Enable or Disable, Edit in Form, Rescale), CORE-301 (JSON Patch on the file that holds the instance), ENH-001.
- Spec check: 2026-11-12, Core spec 0.38 (the Module Contract and the implementation plan were not checked; the code was not checked). Searched "CORE-326:", "CORE-322:", "Add module" (no hit) and "new instance" (only the restart of an instance, CORE-191). Found: CORE-326 covers moving, resizing, and listing disabled instances with an Enable action; CORE-322 names the four tabs and the History actions; CORE-328 (from the earlier check, 2026-11-07) lists the toolbar controls of a selected instance, with Enable or Disable and no remove. No requirement defines adding or removing a module instance in the UI. Result: the user's assumption is confirmed as far as searched. Not checked: the Modules and Catalog pages of the admin (whether they install or add modules), and whether the Form tab, generated from the config schema, lets the `modules` list be added to or removed from.
- Status: rejected — not a spec gap (found on 2026-11-12, see the History); the report continues as ISS-011. The entry stays in the log (entries are not deleted).
