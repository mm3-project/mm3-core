# ENH-010 — Show that a section is not in the config, and let it be added from the Form
- Reported: 2026-11-12 (from ISS-013, whose editing part is a duplicate of ISS-012)
- Type: enhancement (the spec has no rule on how the Form shows an optional section that is absent from the config; see Spec check)
- Priority: P3 (proposed by Claude: the user accepted the recommendation to keep the point but gave no priority; a workaround exists; the user can change it)
- Area: admin UI, Form view (sidebar and section form)
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: the user saw the `audio` and `backup` entries of the Form sidebar greyed out and took them as disabled ("I have audio speakers connected but in admin the audio entry is greyed out"). The grey meant only that the section is not in the config; adding `audio: {...}` and `backup: {}` to the YAML turned them on (ISS-012, ISS-013).
- Workaround: add the section to the YAML view first (for `pages`, with at least one page; see ISS-012). Since PR #97 (ISS-012 fixed) the first edit in an absent section creates it, so the workaround is no longer needed for editing; only the grey display remains.
- Expected / proposed: defined in Core 0.39 as CORE-379 (extends the Form view of 6.4 and CORE-301): an optional top-level section absent from the config is listed like the others, not greyed out, with the label "Not in config, defaults apply" (a core catalog key), and its fields show the defaults as placeholders; the first edit creates the section in the same draft step; "Add section" writes its smallest valid content (`{}`, or for `pages` a list with the page `main`) and "Remove section" deletes a present optional section, each one draft step.
- Requirements: Core 0.39: CORE-379 added. Related: the Form view requirement of the editor, CORE-301 (Form reads `documents`), CORE-244 (every `backup` key optional), CORE-230 (`pages`).
- Spec check: 2026-11-12, Core spec 0.38 (the Module Contract, the plan and the code were not checked). Searched "grey" (no hit) and "absent" (hits only in other contexts: CORE-277, CORE-291, CORE-293, CORE-316, kiosk volume). No requirement says how the Form shows an absent optional section. Result: a gap, as recommended.
- Status: in progress — spec written in Core spec 0.39 (CORE-379, Document history row 0.39 with `Source: … ENH-010`; spec sync PR #100, squash-merged 2026-11-13); code written as PR E, PR #108, merged into main (d643eaf). The user decides when it is fixed.
