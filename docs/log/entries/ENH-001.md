# ENH-001 — No page creation or deletion in the admin UI
- Reported: 2026-11-07
- Type: enhancement (the user reported it as "a gap" without naming a type; Claude classified it as an enhancement because the spec does not cover the behaviour, see Spec check; the user can change this)
- Priority: P2 (proposed by Claude: not stated by the user; a workaround exists, so it is not blocking; the user can change it)
- Area: core, admin UI (layout view and pages)
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "there is no page creation/deletion function in the UI" (as reported; the user thinks it is a gap)
- Workaround: edit the `pages` section in the YAML (the user is not sure that this works). The spec supports it for creation: `pages` is a top-level config key (CORE-230) and the admin has a YAML tab (CORE-322). Not verified in practice, and not verified for deletion or for the Form tab.
- Expected / proposed: defined in Core 0.39 as CORE-376 (extends CORE-230 and CORE-242): beside the page selector of the Layout view, "New page" (an id checked against CORE-230 and a title in the session language; without a `pages` block it creates one with `main` and the new page, `default: main`), "Rename page" (title in the session language only, never the id) and "Delete page" (not for the last page; removes the page from `pages.list`, from every instance's `pages` list and its `positions.<page>`; an instance left with no page gets `disabled: true`, the user's choice of 2026-11-13; a deleted `default` moves to the first remaining page), each one draft step.
- Requirements: Core 0.39: CORE-376 added. Related: CORE-230 (the `pages` key), CORE-242 (page selector), CORE-322 (admin config page), CORE-327 (page writes).
- Spec check: 2026-11-07, Core spec 0.38 (the Module Contract and the implementation plan were not checked; section 6.9 was read only through the requirements found by search, not in full). Searched "page selector", "new page", "6.9", "CORE-230", "CORE-326", "CORE-327". Found:
  - CORE-230: `pages` is an optional top-level config key; without it there is one implicit page `main`; page ids match `[a-z][a-z0-9_]{0,31}` and are unique; at most 32 pages; `default` names a listed page; `title` is a LocalizedText.
  - CORE-242 and CORE-325: the Layout view has a page selector that selects the page whose layout is edited and previewed; nothing says it creates or removes pages.
  - CORE-326 and CORE-327: overlay edits move and resize instances and write `positions.<page>` or `position`; they do not create or delete pages.
  - CORE-322: `/admin/config` has the tabs Layout, Form, YAML and History; no text found on creating or deleting pages in any of them.
  Result: the user's assumption is confirmed as far as searched: no requirement defines creating or deleting a page in the UI. Not found, and so not claimed: whether the Form tab, which is generated from the config schema, already lets the `pages` list be added to or removed from; what validation says about instances that name a page that does not exist.
