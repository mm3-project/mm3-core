# ENH-007 — Connection indicator for the MQTT bridge in the admin screen
- Reported: 2026-11-12
- Type: enhancement (as reported by the user: "also add in admin screen feedback for connection")
- Priority: P2 (proposed by Claude: the user gave "high pri" for the issue ISS-007 in the same message and none for this request; it is the means to see ISS-007 without reading logs; the user can change it)
- Area: admin UI, MQTT bridge
- Spec versions at report: Core spec 0.38, Module Contract 1.0 rev 15
- Description: "also add in admin screen feedback for connection (green connected, red error, grey not connected)" (as reported). Read as a status indicator for the MQTT connection in the admin pages, in three states: green when connected, red on an error, grey when not connected. Not stated: on which admin page it appears; whether the same is wanted for other connections (Home Assistant, for example, if it uses its own connection); whether grey means "bridge off" (no `engine.mqtt`) or "configured but not connected yet"; whether the error text should be shown. Settled on 2026-11-14 by the user's answers (see History): the header of every admin page; a fourth state, amber, for "configured, not connected yet"; a text label with every colour.
- Workaround: `mm3 diag check` (CORE-339 says it reports the bridge as ok, fail or skip) and `GET /api/v1/status`, both from the command line or an API client; the log. Not verified in practice.
- Expected / proposed: defined in Core 0.41 as CORE-381 (extends CORE-305, CORE-304 and CORE-378): every admin page except `/admin/login` shows in its header a coloured dot with a text label for the MQTT bridge, read from the `mqtt` object of the status: `mqtt` null (bridge off) grey "MQTT off"; connected green "MQTT connected"; not connected with no error (not connected yet, or between retries) amber "MQTT connecting"; not connected with an error red "MQTT error". The tooltip gives `since` as a local date and time and, in the red state, the `error` text. While the admin channel is closed (for example while the engine restarts) it shows grey "MQTT status unavailable". It follows the `status` topic of `/admin/ws` and does not poll. The admin home `/admin` becomes a live status view (engine version and uptime, configuration version, current page, clients, kiosk, MQTT with `since` and `error`; a mismatch or a failure is highlighted) and `/admin/debug` shows the same MQTT line. Labels are core catalog keys in the admin language. Not done, as decided: the same indicator for other connections (Home Assistant has none of its own; it goes through the MQTT bridge); the look in a new admin style (ENH-005).
- Requirements: Core 0.41: CORE-381 added. Already required and now built: CORE-305 (the status route; "the admin home and the debug overview show it") with CORE-339 (adds `mqtt: {connected, since, error}` to the status) and CORE-378 (the admin home with the status). Related: CORE-304 and CORE-317 (the `status` topic), CORE-309 (admin language), CORE-63 (no inline script or style), CORE-322.
- Spec check: 2026-11-12, Core spec 0.38 (the Module Contract, the implementation plan and the code were not checked). Searched "CORE-339", "bridge's health" and "CORE-305" (the last added on 2026-11-12 after the first version of this check) and read CORE-305 and CORE-339. Found: the status route carries `mqtt: {connected, since, error}`, which supplies the three states. CORE-305 says the admin home and the debug overview show the status (named there for the kiosk: mismatches and failures highlighted), and CORE-339 extends that status with `mqtt`, so the admin home should already show the MQTT state in some form; whether it does, and how, is not specified, and the code was not checked. Result: not a pure gap, correcting the first version of this entry. The state is required to be visible on the admin home and the debug overview; the user's report suggests it is not shown clearly (or not at all), which would be a deviation to confirm in the running admin, and the three-colour indicator with its mapping is an enhancement on top of it.
  Code check, 2026-11-14, Core spec 0.40, mm3-core main at 025e9f7: `/admin` was the placeholder `admin_home_page` (text `CORE_WEB_ADMIN_PENDING`) with no status, and the overview of `/admin/debug` had engine, clients and kiosk cards but no MQTT line. So two parts were deviations from CORE-305 (the admin home had no status; the debug overview had no MQTT) and the indicator itself was a spec gap, closed by CORE-381. The status route and its `mqtt` object (CORE-339) and the `status` topic of `/admin/ws` (CORE-304, CORE-317) already existed.
